# P07: локальное файловое хранилище

`BlobStore` — типизированный контракт, `LocalBlobStore` — синхронная реализация.
Потребитель явно передаёт корень общего volume и `max_bytes` (для загрузки —
`Settings.limits.upload_bytes`). Хранилище не создаётся при импорте API.
В асинхронном обработчике блокирующие операции следует выполнять вне event loop.
HTTP upload и PDF-пайплайн на этом шаге не добавлены.

```python
from pathlib import Path
from article_graph.documents.blob_store import BlobNamespace, LocalBlobStore

store = LocalBlobStore(
    Path("/data/blobs"), max_bytes=settings.limits.upload_bytes, limits=settings.limits
)
with Path("input.md").open("rb") as stream:
    blob = store.put_source(stream, content_type="text/markdown")
with store.open(BlobNamespace.SOURCES, blob.content_hash) as stream:
    # Потребитель сам закрывает поток; содержимое не логируется.
    pass
```

Исходники находятся в `sources/<sha256>`, результаты обработки — отдельно в
`artifacts/<sha256>`. SHA-256 считается по исходным байтам, без нормализации.
Имени клиентского файла в интерфейсе нет. Чтение разрешено только по enum
пространства и полному lowercase SHA-256; абсолютные пути, traversal, symlink
и Windows junction под корнем отклоняются. Потоки открываются только для чтения.

При записи читаются блоки максимум 64 KiB, последний запрос — максимум остаток
лимита плюс один байт. Превышение обнаруживается без полной загрузки потока;
ошибка `payload_too_large` не публикует blob. Для артефактов действует тот же
явно заданный лимит экземпляра хранилища, без проверки формата.

Сначала создаётся уникальный `.pending-*` на том же filesystem, затем выполняются
flush/fsync, закрытие и проверка формата. Атомарная публикация использует
`os.link(pending, hash_path)` с последующим удалением временного имени:
это перенос через hard link без перезаписи существующего назначения.
Финальное имя появляется только для полного файла. При повторной/конкурентной
записи существующий файл не заменяется, его hash проверяется ограниченным
чтением. Несовпадение означает ошибку целостности, а не попытку ремонта.
Нужен локальный filesystem с поддержкой атомарных hard links (например, NTFS
или ext4); fallback на копирование/неатомарную запись отсутствует.

`FormatValidator` принимает `text/plain`, `text/markdown`, `application/pdf`
(параметры Content-Type игнорируются при выборе формата). Markdown — непустой
UTF-8, декодируемый строго и потоково, без бинарных управляющих символов, кроме
табуляции и переносов строк. Это обычный текст Markdown, специальный синтаксис
не обязателен. PDF определяется по `%PDF-` в начале и открывается настоящим
PDFium-парсером; требуется хотя бы одна страница. Несоответствие объявленному
типу отклоняется. Повреждённый PDF/UTF-8 даёт `invalid_document`, пустой Markdown
— `validation_error`; неподдерживаемый/несовпавший тип — `unsupported_media_type`.
С P10 PDFium импортируется через PEP 810 только в ограниченном дочернем процессе.
Входная проверка учитывает timeout, страницы, Linux memory budget и отклоняет
encrypted PDF. Страницы здесь не рендерятся, текст не извлекается.
Полная обработка страниц выполняется [PDF-preprocessor](pdf.md).

Корень должен принадлежать приложению: внешним процессам нельзя менять файлы,
каталоги и links параллельно с операциями хранилища. Проверка путей не является
защитой от привилегированного локального процесса, меняющего дерево между
проверкой и открытием. Immutable здесь означает отсутствие операций изменения
и перезаписи в интерфейсе приложения, а не запрет записи владельцу filesystem.

Обработанные исключения удаляют staging. Убийство процесса/потеря питания может
оставить `.pending-*`; после публикации и до регистрации БД возможен непривязанный
полный blob. Уборка таких файлов — будущая отдельная задача. Общей транзакции
с Neo4j и гарантии сохранности directory entry при потере питания здесь нет.

Проверки P07: `uv run --frozen pytest tests/documents/test_blob_store.py`. Набор проверяет
границы размера, traversal/junction, неверный UTF-8 и формат, настоящий PDF,
ленивую загрузку PDFium в отдельном процессе, повторные записи, конкуренцию
потоков и процессов, целостность и очистку после ошибок чтения/fsync/публикации.
